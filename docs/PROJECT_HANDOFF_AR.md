## 1. ما هو النظام

نظام ERP داخلي لمصنع ملابس (جلابيات أساساً) يغطي الدورة الكاملة:

```
مورد → فاتورة شراء → استلام خامات (جزئي/كلي) → مخزن الخامات
عميل → طلب بيع → أمر تشغيل → صرف خامات → استلام الورشة (WIP)
→ 5 مراحل إنتاج (قص، خياطة، تشطيب، كي، تعبئة) → تسوية خامات الورشة
→ استلام المنتج التام لكل مقاس → مخزن التام → تسليم للعميل → تحصيل → أرصدة
+ الخزينة والاعتمادات، العهد والمصروفات، الرواتب، الجرد، سجل التدقيق، لوحة التشغيل والتقارير
```

**المخازن الثلاثة:** الخامات (raw)، التشغيل/الورشة (WIP)، المنتج التام (finished_goods). أنواع مواقع دفتر المخزون: `warehouse`، `in_transit`، `discrepancy` (الأخير بلا `warehouse_id` — يُستبعد من أرصدة المخازن).

## 4. ما هو منجز — Backend (حسب الوحدة)

> كل المسارات تحت `/api/v1`. الصلاحية بين قوسين.

**المصادقة:** `/auth/config`، `/auth/local-login` (تطوير فقط)، `/auth/me` (هوية + صلاحيات).

**الدليل `/catalog`:** تصنيفات (شجرة، CRUD، حذف محمي للمعيارية) — أصناف بدورة اعتماد: draft → submit → approve/reject → reopen، تعطيل/إعادة تفعيل، طلبات تعديل لصنف معتمد (revisions) مع اعتماد/رفض/إلغاء، سجل تاريخ، خطوط الاستخدام (usages)، الوحدات (قراءة فقط). الحراسة: `inventory:view` للقراءة، `inventory:manage` للإنشاء/التعديل، `catalog:item:approve` و`catalog:item:manage_revisions` للاعتماد.

**الإنتاج `/production`:** الموديلات `GET/POST/PATCH /products` و`POST /products/{id}/variants` (`production:templates:manage`) — **أُضيفت في جولة العرض**؛ القوالب (BOM) `GET/POST /templates`؛ أوامر التشغيل (إنشاء، عرض، خامات المسودة إضافة/حذف)، `POST /orders/{id}/dispatch` (`warehouse:dispatch`)، `POST /orders/{id}/receive` و`/finished-receipt` (`warehouse:confirm_receipt`)، المراحل والتراجع (`production:stages:manage`)، العيوب، العجز، ملخص WIP، `POST /orders/{id}/material-reconciliations` (تسوية الاستهلاك الفعلي والمرتجع والهالك)، `POST /orders/{id}/close` (لا يغلق قبل اكتمال المراحل الخمس وتصفير رصيد الورشة)، `/performance/summary` (مدد معيارية لا مقاسة)، `/catalog-items` (يعيد حالة الاعتماد الفعلية — أُصلح)، `/warehouses`. كل العمليات الحساسة تدعم `Idempotency-Key`.

**المخزون `/inventory`:** `/stock`، `/finished-goods-balances` (لكل مقاس)، `/ledger`، الجرد الكامل: إنشاء (لقطة) → بدء العد → العد → إرسال → مراجعة → اعتماد → ترحيل تسويات / إلغاء، مع سجل تدقيق وقيود الجرد. الترحيل يُرفض إن تغيّر رصيد الصنف بعد فتح الجلسة.

**العملاء `/customers`:** قائمة/إنشاء/تعديل، حساب العميل (طلبات + مستحق + مدفوع معتمد)، طلبات البيع، التسليمات المعلقة، تسجيل التسليم، المرتجع، فحص المرتجع (حاوية «تحت الفحص» قبل العودة للمخزون القابل للبيع)، التحصيل (`finance:payments:manage` — ينشئ سنداً **معلقاً** في الخزينة)، إنشاء أمر تشغيل مرتبط بطلب تصنيع خاص.

**المالية `/finance`:** الحسابات، السندات النقدية (إنشاء `finance:cash:manage`، قرار `finance:cash:approve` مع منع الذاتي)، العهد (إنشاء، معاينة تسوية، تسوية — رد النقدية سند تحويل معلق)، المصروفات اليومية (سند معلق)، الموردون (إنشاء + **PATCH أُضيف** — الكود ثابت)، فواتير الموردين (خصم لكل بند، حالة `awaiting_receipt/partially_received/received/cancelled`)، الاستلام الجزئي (`suppliers:receive`)، طلب دفع المورد (سند معلق؛ سقف = إجمالي الفاتورة قبل اكتمال الاستلام، وقيمة المستلم بعده)، دفتر الأستاذ (`/gl/*`).

**الرواتب `/payroll`:** الموظفون (إنشاء/تعديل)، الحضور (مرجع فقط)، الفترات، الإعداد (`calculate`)، تعديل يدوي مسبب لكل كشف، `POST /periods/{id}/disburse` = **إرسال للصرف** (سند صرف واحد معلق في الخزينة؛ لا تُصرف فترة مرتين). **لا معادلات رواتب** (حُذفت /240 و/30 و×1.5 بقرار).

**التقارير `/reports`:** `summary` (لوحة الإدارة)، `inventory` (أرصدة المخازن الحقيقية فقط + قائمة `transfer_discrepancies` منفصلة — أُصلح)، المديونيات، المستحقات، كشوف حساب العميل/المورد، التدفق النقدي، العهد، تقييم المخزون وWIP، COGS، تحليل تكلفة أمر، P&L، الميزانية، ميزان المراجعة، الأستاذ، تحليل المصروفات والإيرادات. **القوائم المالية الرسمية مخفية من الواجهة** (لا أرصدة افتتاحية، وتصنيف المصروفات بكلمات الوصف).
