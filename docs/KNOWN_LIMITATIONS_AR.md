# القيود المعروفة — Qema ERP (نسخة التسليم التجريبي · نوفمبر 2026)

هذه القائمة صريحة عمداً حتى لا يُفترض أن النظام يغطي ما لم يُنفذ أو لم يُعتمد بعد. القسم «أ» لصاحب المصنع والموظفين، والقسمان «ب» و«ج» للإدارة ومسؤول النظام.

## أ. ما لا يتيحه النظام حالياً (للمستخدمين)

| الموضوع | الوضع الحالي | البديل المتاح الآن |
|---|---|---|
| إدارة المستخدمين والأدوار | لا توجد شاشة لإضافة مستخدم أو تغيير دوره | مسؤول النظام ينشئ الحساب ويسند الدور (راجع دليل التشغيل) |
| وحدات القياس | تُعرض فقط؛ لا يمكن إضافة وحدة أو تعديلها من الواجهة، ولا يوجد تحويل بين الوحدات | استخدام الوحدات الموجودة؛ إضافة وحدة تتطلب قراراً ومسؤول النظام |
| الرصيد الافتتاحي | لا توجد شاشة «رصيد افتتاحي» | المخزون: جرد افتتاحي معتمد. الخزنة: سند قبض بوصف «رصيد افتتاحي» يسجله المدير المالي فيُعتمد فوراً (أو يعتمده المدير المالي إن أنشأه غيره) |
| مرتجعات العملاء | لا توجد شاشة لتسجيل مرتجع من العميل، رغم ظهور خانة «مرتجع تحت الفحص» في مخزن المنتج التام | لا يوجد بديل داخل النظام حالياً |
| إلغاء أو عكس مستند معتمد | لا توجد شاشة لعكس سند نقدي معتمد أو إلغاء طلب عميل أو فاتورة مورد | التصحيح بمستند جديد معاكس بعد قرار الإدارة |
| صرف إضافي لأمر تشغيل | لا يمكن صرف خامات إضافية لأمر بعد الصرف الأول (مثلاً لإصلاح عيوب) | إنشاء أمر تشغيل جديد |
| التحويل بين المخازن | لا يوجد تحويل يدوي بين المخازن خارج أوامر التشغيل ومرتجعات الورشة | — |
| حجز المخزون لأوامر التشغيل | إنشاء الأمر لا يحجز الخامات؛ المتاح المعروض لا يطرح احتياجات أوامر أخرى لم تُصرف | مراجعة الأوامر المسودة قبل الصرف |
| مستلزمات حسب القماش أو اللون | المستلزمات لكل موديل ومقاس فقط؛ القماش واللون مواصفات نصية في سطر الأمر | — |
| الإدخال اليدوي للخامات في الأمر | الشاشة تعتمد على مستلزمات المقاس فقط؛ يمكن إضافة خامة يدوية على أمر مسودة بعد إنشائه | — |
| الماكينات | الصفحة غير مكتملة وأُخفيت من القائمة | — |
| القوائم المحاسبية الرسمية | لا ميزانية ولا قائمة دخل ولا ميزان مراجعة | التقارير التشغيلية: الخزينة، مديونيات العملاء، مستحقات الموردين، المخزون |
| التنبيهات الخارجية | لا رسائل SMS أو واتساب أو بريد | صندوق المهام داخل النظام |
| الحضور بالبصمة | غير مرتبط بأجهزة بصمة | تسجيل الحضور يدوياً للمراجعة فقط |

## ب. قرارات عمل تنتظر إدارة المصنع (لم يخترع النظام قاعدة بدلاً منها)

| الموضوع | الوضع الحالي في النظام | المطلوب من المصنع |
|---|---|---|
| قواعد الحوافز والخصومات | النظام يدعم الراتب الشهري وأجر اليومية، والحوافز والخصومات تُدخل يدوياً في كشف كل فترة مع سببها (مبلغ، نسبة، أو كمية × سعر). لا يُطبق أي خصم للغياب أو التأخير تلقائياً | اعتماد مكتوب للقواعد إن أُريد حسابها آلياً |
| طريقة تقييم المخزون | متوسط تكلفة مرجح على أساس حركات الوارد ذات التكلفة | اعتماد الطريقة (متوسط / الوارد أولاً / تكلفة معيارية) |
| تكلفة المنتج التام | تكلفة الخامات المستلمة بالورشة فقط ÷ الكمية المستهدفة؛ لا أجور ولا مصروفات غير مباشرة | قرار تحميل الأجور والمصروفات غير المباشرة |
| تجميد الحركة أثناء الجرد | لا يوجد تجميد؛ الترحيل يُرفض إذا تغير رصيد الصنف بعد فتح الجلسة | هل تُجمد الحركة أثناء الجرد؟ |
| تأكيد استلام المنتج التام | متاح لأمين المخزن والمدير العام | هل يكفي ذلك أم يُقصر على أمين المخزن؟ |
| تخصيص كل مخزن لأمين محدد | أمين المخزن يعمل على المخازن الثلاثة | هل يلزم ربط كل أمين بمخزن؟ |
| الأسعار والخصومات | من يدير العملاء (المدير المالي والمدير العام) يحدد السعر والخصم | من يعتمد الأسعار والخصومات؟ |
| التحويلات البنكية | التحصيل «تحويل بنكي» يُسجل في الخزنة الرئيسية | هل يُفتح حساب بنكي مستقل؟ |
| الدفعات المقدمة للموردين | مسموح بالسداد حتى إجمالي الفاتورة قبل اكتمال الاستلام، وبقيمة المستلم فقط بعد اكتماله | اعتماد السياسة |
| الإلغاء والعكس | لا توجد قواعد معتمدة | قواعد الإلغاء والعكس ومن يعتمدها |
| المدير العام كمنشئ في الجرد ودليل الأصناف | المدير العام هو المعتمد الوحيد؛ إذا أنشأ الجلسة أو الصنف بنفسه لا يستطيع أحد اعتمادها | تعيين معتمد ثانٍ أو أن يترك الإنشاء لأمين المخزن |
| معنى «المواصفة» في المستلزمات | المستلزمات مربوطة بالموديل والمقاس | هل تختلف المستلزمات لنفس المقاس حسب القماش أو اللون؟ |

## ج. ملاحظات تقنية لمسؤول النظام

1. **تحديثات قاعدة البيانات غير المطبقة:** ملفات الترحيل `20261109_0018` حتى `20261109_0021` موجودة في المشروع ولم تُطبق على قاعدة التطوير أو العرض أو المصنع. الترحيل `0021` (إيقاف الموديلات والمقاسات) لم يُطبق على أي قاعدة. **تشغيل النسخة الحالية من الخادم على قاعدة لم تُطبق عليها هذه الترحيلات يفشل** في شاشات الموديلات والإنتاج والرواتب. يجب تطبيق `alembic upgrade head` بعد أخذ نسخة احتياطية وبموافقة؛ على قاعدة المصنع الأونلاين يتم ذلك فقط عبر `deploy/migrate.sh` (راجع `DEPLOYMENT_GUIDE_AR.md`).
2. **دفتر الأستاذ العام:** العمليات الجديدة تُرحّل قيودها داخل نفس المعاملة، لكن لا توجد أرصدة افتتاحية محاسبية، والحركات السابقة لترحيل 0016 ليس لها قيود، وتصنيف المصروفات يعتمد على كلمات في الوصف (صيانة/تشغيل/إنتاج ← 5300، غير ذلك ← 5400) والرواتب على 5200.
3. **الكميات** ما زالت مخزنة كأرقام عشرية ثنائية (Float) في جداول الإنتاج والمخزون؛ النقدية والرواتب والتكاليف ومستلزمات التصنيع دقيقة (Numeric).
4. **منع الرصيد السالب** مطبق في التطبيق مع أقفال متزامنة لكل صنف/مخزن، وليس بقيد في قاعدة البيانات.
5. **تقارير الفترات** نوافذ متحركة بتوقيت UTC (مثلاً «شهري» = آخر 30 يوماً) وليست أشهراً تقويمية بتوقيت القاهرة.
6. **تكلفة المرتجع المعدوم** تُحمّل على حساب 5200.
7. **مؤشرات أداء المراحل** تعرض مدداً معيارية وليست مقاسة فعلياً.
8. **واجهة برمجة أوامر التشغيل** ما زالت تقبل خامات يدوية دون مستلزمات (`custom_materials`) للتوافق مع السكربتات القديمة؛ الواجهة لا تستخدم هذا المسار.
9. **لم يُتحقق منه:** تشغيل GitHub Actions فعلياً، اعتماد Supabase الفعلي، وفحص ثغرات الحزم (npm audit / pip-audit).
