# خريطة بيانات مبدئية

هذه خريطة مفاهيمية لتقسيم البيانات وليست schema نهائية. تُراجع مع قواعد العمل قبل إنشاء migrations. الأرصدة مشتقة من مستندات وحركات معتمدة؛ لا يسمح بتغييرها من نموذج مباشر.

## الهوية والتدقيق

- `auth.users`: هوية الدخول التي تديرها خدمة Supabase Auth.
- `user_profiles`: بيانات العرض وحالة المستخدم وربط الهوية ببيانات النظام.
- `roles`, `permissions`, `user_roles`, `role_permissions`: تعريف الأدوار والأفعال والوحدات.
- `audit_events`: الفاعل، الحدث، نوع/معرف السجل، الوقت، معرف الطلب، وفرق القيم المسموح بتدقيقه. استبعاد tokens وكلمات المرور والبيانات الخاصة غير اللازمة.

## الدليل والمخازن

- `items`: كود واسم ونوع وفئة وحالة وسمات الصنف.
- `units`: وحدات قياس، مع `item_unit_conversions` إذا اعتمد المصنع تحويلًا لصنف.
- `warehouses`: المخازن التشغيلية الثلاثة.
- `warehouse_item_thresholds`: حد النقص للصنف في المخزن، إن كان الحد لكل مخزن.
- `stock_documents` + `stock_document_lines`: رأس المستند وبنوده ونوعه وحالته ومنشئه ومعتمده.
- `stock_ledger_entries`: أثر حركة كمية غير قابل للحذف، مرتبط بمستند وسطر ومخزن وصنف ووحدة. سجل ledger هو مصدر رصيد المخزون.
- `inventory_counts`/`adjustments`: الجرد والفروق كوثائق تسوية، عند اعتماد شكلها.

## الإنتاج

- `production_orders`: رقم الدفعة، المنتج الناتج، الهدف، الحالة، المخطط الزمني والمسؤول.
- `production_bom_versions` + `production_bom_lines`: قائمة مواد مرجعية بإصدارات؛ إنشاءها مشروط بإقرار وصفات المقاسات/الألوان.
- `production_material_issues`: المواد المصروفة للدفعة، مرتبطة بحركة مخزنية.
- `production_consumptions`, `production_returns`, `production_waste`: الكميات الفعلية والسبب والمصدر والمراجع.
- `production_outputs`: الناتج الجيد والعيب/إعادة التشغيل إن اعتمدت.
- `production_cost_summaries`: ملخص تكلفة محفوظ/قابل لإعادة التحقق مع تفاصيل طريقة الحساب وإصدار السياسة، وليس رقمًا مبهمًا.
- استلام المنتج التام يسجل أيضًا كحركة ledger في مخزن المنتج التام.

## العملاء والمبيعات

- `customers`: بيانات العميل اللازمة لإدارة الطلب.
- `sales_orders` + `sales_order_lines`: الطلب والأسعار والكميات والموعد والحالة.
- `deliveries` + `delivery_lines`: الكمية المسلمة فعليًا وربطها بالطلب والمخزن.
- `sales_returns` + lines: المرتجعات وأسبابها ونتيجة فحص الحالة وحركة الرصيد.
- التحصيلات والأرصدة الائتمانية ليست مؤكدة في النطاق؛ لا تنشأ جداول مالية قبل اعتماد قرارها.

## الموظفون والرواتب

- `employees`: بيانات العمل الضرورية فقط وحالة الموظف والقسم.
- `pay_periods`: الفترات وحالة المسودة/المراجعة/الاعتماد/الإغلاق.
- `payroll_runs`, `payroll_entries`: كشف الموظف والفترة ونسخة السياسة المستخدمة.
- `payroll_components`: بند تفصيلي موجب أو سالب، النوع والقيمة ووحدة الحساب والمصدر أو السبب.
- `salary_advances`, `advance_installments`: السلف والأقساط والمبالغ المتبقية ضمن سياسة معتمدة.
- وصول مقيد؛ لا تُنسخ بيانات الرواتب إلى سجلات التشغيل العامة أو تحليلات خارجية.

## روابط البيانات وقواعد الاتساق

- كل حركة مخزنية مرتبطة بمستند معتمد وبنوده ومصدرها التشغيلي.
- طلب العميل لا يعدل رصيد المخزون وحده؛ التسليم المعتمد هو ما ينشئ حركة صرف للمنتج التام إذا اعتمدت هذه السياسة.
- إغلاق دفعة الإنتاج مرتبط بإثبات المواد المستخدمة/الراجعة/الهالكة والناتج الجيد وتسوية الفروق.
- اعتماد كشف راتب يرتبط بالفترة والمستخدم المعتمد ومصدر كل بند، ويصبح غير قابل للتعديل الصامت.
- كل جدول أعمال يحمل معرفًا غير متوقع، `created_at`, `created_by`, وحقول الاعتماد اللازمة؛ لا تكرر التاريخ والمستخدم في أنظمة أخرى إلا لسبب محدد.
- استخدم foreign keys وunique constraints وcheck constraints بقدر ما تنطبق، وعمليات transaction لحفظ التناسق.
- سياسة حذف/احتفاظ بيانات العميل والموظف تحتاج اعتمادًا. السجلات المعتمدة تحفظ وفق سياسة المصنع والقانون الذي يحدده مختصه.

## قرارات schema التي يجب حسمها

طريقة التقييم والتكلفة، حجز المخزون، حدود الدقة، وحدات المقاسات/الألوان، سياسة الرصيد السالب، فصل المستند عن دفتر الحركة، سياسة بيانات الموظف، وكيفية إغلاق/فتح دفعة أو كشف راتب. راجع `docs/OPEN_DECISIONS_AR.md`.
